# Chatbot 3.1.0 — prod handover (2026-11-17)

**Image:** `tiledesk/tiledesk-chatbot:3.1.0` (Docker Hub, built from tag `3.1.0` on `main`).
**Code:** `main` @ `3dab56e4` = 3.0.9 + the agent execution traceability feature (merge of
`feature/execution-traceability`) + version commit. Changelog: `CHANGELOG.md`, section 3.1.0.

## What the release changes on prod when deployed as is

- **Nothing for execution traceability**: tybot records, seals and controls executions only with
  `EXECUTIONS_ENABLED=true`, and prod does not set it. With it off: no AMQP events, no Redis stop/resume
  keys, no pause notice; the tracing hooks in the directives are no-ops.
- **Two engine fixes ship regardless of the switch** (found by the "all blocks" agent on stage, verified there
  since 2026-11-12):
  - *If open hours*: its callback could be called twice, so the action after it ran twice;
  - *Change department*: the flow hung when no department matched or the department had no bot.
- Prod runs 3.0.9 today (tiledesk-argo prod 1a40fe2a); everything in 3.0.9 is unchanged.

## How to deploy

Same as any chatbot release: in tiledesk-argo `prod` (`helm/values.yaml`) set the `tiledesk/tiledesk-chatbot`
image tag (today `3.0.9`) to `3.1.0`, and sync `my-tiledesk-prod` as usual.

**Do not** add `EXECUTIONS_ENABLED` / `executionsAddon.chatbot.enabled` yet: the switch-on is a separate step
(owner: execution traceability, see `2026-11-17-execution-traceability-prod.md`). When it comes, tybot also
needs `EXECUTIONS_AMQP_URL` (the platform's `CLOUDAMQP_URL`), `EXECUTIONS_SERVICE_URL`
(`http://tiledesk-executions-internal:3100`, namespace `my-tiledesk-prod`) and four keys from Secret
`tiledesk-executions` (seal public key, seal kid, state hash key, service token) — all rendered by the
`executionsAddon` block of tiledesk-argo, ready on branch `release/executions-addon-prod` (to be rebased on
the current prod).
