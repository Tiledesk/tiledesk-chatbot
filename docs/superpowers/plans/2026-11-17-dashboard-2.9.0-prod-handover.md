# Dashboard 2.9.0 — prod handover (2026-11-17)

**Image:** `tiledesk/tiledesk-dashboard:2.9.0` (Docker Hub, built from tag `2.9.0` on `master`).
**Code:** `master` @ `2d233ffa6` = 2.8.43 + the Agent Executions feature (merge of `feature/execution-graph`)
+ version commit. Changelog: `CHANGELOG.md`, section 2.9.0.

## What the release changes on prod when deployed as is

- **Nothing visible for Agent Executions**: every new page is behind `EXECUTIONS_BASE_URL`, which prod does
  not set. With it empty (or the unreplaced `${EXECUTIONS_BASE_URL}` placeholder) the Executions tab, the
  per-agent Executions button, the execution settings and the execution rows in Activities stay hidden.
- **nginx**: `index.html` and `assets/i18n/*.json` are now served with `Cache-Control: no-cache` (re-checked on
  every load, 304 when unchanged), so new labels show after a deploy without a hard reload. Hashed bundles keep
  their default caching. This applies to the image's own nginx.
- Everything else in 2.8.43 is unchanged.

## How to deploy

With the team's usual dashboard release process, on whichever of the two targets prod uses:

- **panel.tiledesk.com** is a static build on S3/CloudFront (its `dashboard-config.json` carries unreplaced
  `${...}` placeholders): build tag `2.9.0` and publish it as usual. Keep `EXECUTIONS_BASE_URL` out of the
  published `dashboard-config.json` (or leave it as the `${EXECUTIONS_BASE_URL}` placeholder): the feature
  stays hidden.
- The in-cluster dashboard (tiledesk-argo `prod`, image `tiledesk/tiledesk-dashboard`): set the tag to
  `2.9.0` and sync `my-tiledesk-prod` as usual.

**Do not** add `EXECUTIONS_BASE_URL` / `executionsAddon` yet: the switch-on is a separate step done after the
chatbot and server releases (owner: execution traceability, see
`2026-11-17-execution-traceability-prod.md`). When it comes, the value is
`https://eu.rtmv3.tiledesk.com/executions/api/v1/` (the executions API runs on prod since 2026-11-17, Argo app
`tiledesk-executions`, namespace `my-tiledesk-prod`; CORS already allows `https://panel.tiledesk.com`).

## Checks after the deploy

1. The dashboard loads and works as before (login, conversations, agents list, settings).
2. No "Executions" tab under Monitor and no Executions button on agents (expected while the switch is off).
3. `curl -sI https://panel.tiledesk.com/v3/dashboard/assets/i18n/en.json | grep -i cache-control` →
   `no-cache` **only if** prod serves the dashboard from this image's nginx. If prod serves the static files
   from S3/CloudFront (panel.tiledesk.com answers S3 errors for unknown paths), the header comes from the
   bucket/CloudFront settings instead: set `Cache-Control: no-cache` on `index.html` and `assets/i18n/*` there
   to get the same effect.
