**Images** (built from tag `3.4.0` on `master`):
- `tiledeskrepo/tiledesk-server-enterprise:3.4.0` (private, the prod server image)
- `tiledesk/tiledesk-server:3.4.0` (community)
- `tiledesk/tiledesk-server-worker:3.4.0` (server workers)

**Code:** `master` @ `e80c40ca` = 3.3.5 (tybot-connector 3.0.9) + the agent execution traceability support
(merge of `feature/execution-traceability`) + version commit. Changelog: `CHANGELOG.md`, section 3.4.0.

## What the release changes on prod when deployed as is

- **Nothing for execution traceability**: everything it adds is mounted only when `EXECUTIONS_AMQP_URL` is
  set, and prod does not set it. Without it: no publisher of conversation events to the executions
  service, no executions audit consumer, no refire route, no new Activities rows. The jobs worker publishes
  conversation ends only with the same variable.
- **Prod runs 3.3.3 today**, so 3.4.0 also brings the team's 3.3.4 and 3.3.5 (CHANGELOG: AskGPTV2 Pinecone
  reranking sends the reranker model as `name`; tybot-connector bumped to 3.0.8 then 3.0.9). Review those two
  entries with their owners before the deploy.

## How to deploy

Same as any server release: in tiledesk-argo `prod` set the server image tag (enterprise) and the server
worker image tags (`serverworker`, `serverworker-chat21-events`) to `3.4.0`, and sync `my-tiledesk-prod` as
usual.

**Do not** add `EXECUTIONS_AMQP_URL` / `executionsAddon.server.amqp` yet: the switch-on is a separate step
after the chatbot release (owner: execution traceability, see `2026-11-17-execution-traceability-prod.md`).
When it comes, the variable takes the platform's `CLOUDAMQP_URL` (ConfigMap `my-tiledesk-prod-config`) on the
server and both workers; the executions service is already running on prod (Argo app `tiledesk-executions`,
namespace `my-tiledesk-prod`, consuming queue `executions.ingest`).
